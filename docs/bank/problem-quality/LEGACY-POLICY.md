# Optional legacy practice

The user's clarification is the contract: preserve historical integrity, and require active legacy content to earn its place through demonstrated quality and usefulness. Legacy content is optional; it is never needed to inflate default coverage or satisfy a practice-horizon gate.

`Legacy` identifies the 72 families in the original bank, including their reviewed descendants. It does not mean every question written before this release. The three dedicated original ODE constructors are included in this historical origin category, with their actual constructions documented separately.

Settings → Experimental → **Include legacy problems** defaults off, including for profiles created before the preference existed. The saved account preference affects new Test and Rapid question sets. PvP and Multiplayer always exclude legacy and retain the same shared set/order for everyone. Changing the preference never edits issued rounds, history, grades, XP or replays.

An enabled toggle only permits exact revisions listed in `lib/server/legacy-eligibility.json`. It cannot override publication state, source-family withdrawals, global exclusions, supersession or source-hash checks. Every sampled and fallback path uses the same eligibility predicate. The decoded canonical problem is checked again, including its original construction metadata; a missing database alias fails closed. New descendant releases require the origin alias. New questions save the marker and display a **Legacy** badge; historical views can label a recorded known origin without modifying their saved snapshots.

The mandatory build and delta gate, `scripts/bank/quality/verify-legacy-eligibility.mjs`, verifies each report file/hash, independent author/reviewer, unique exact canonical revision/hash, actual family/origin, useful practice rationale, easiest options-visible difficulty, literal-option review and current presentation review. Ordinary source-bound mathematical admission still applies. The report must contain the complete canonical problem; this external binding avoids a circular hash in the immutable record. A fabricated path or an approval flag alone is insufficient.

The current shipping allowlist is deliberately empty. The [72-family evidence audit](legacy-evidence-audit-v1/README.md) found 15 general-screen flags and one additional previously measured rational-pattern signal. The other 56 families have no threshold signal in the reviewed screens; this does not clear their original menus. Prior mathematics and conceptual practice value are preserved, but **zero exact original revisions currently demonstrate every admission requirement**. Future bounded revisions may earn eligibility; enabling the setting is not a promise that any legacy content is available for a chosen filter.

Use [final dispositions](legacy-dispositions-final.json) and [final proposed withdrawals](legacy-withdrawals-final.json) for this release. Earlier blanket drafts remain intact because the evidence audit binds them, but they are superseded. Do not describe all 72 as measured exploitable families or as the same constructor.

Future additions must:

- Demonstrate useful practice at the easiest reasonable level with actual choices visible, preserve misconception explanations and clear every relevant mathematical, option and presentation finding.
- Bind the exact immutable revision and its original construction, retain exposure/equivalence lineage, and supply independently checked report evidence before allowlisting.
- Test default-off, saved preference, renamed descendants, exhausted fallback, withdrawals/rollback, the public Legacy marker and shared competitive policy.
- Evaluate default coverage and sustained horizons without optional legacy. Evaluate an admitted opt-in pool separately, reporting its actual capacity and any narrow-filter limits.

Local API/selector tests verify persistence and exclusion behavior. [Component QA](legacy-component-qa.json) verifies the switch, save-state feedback, wrapping and badge at mobile/desktop widths; that run explicitly does not clear the local preview's blocked KaTeX font assets. No production import or publication is implied.
