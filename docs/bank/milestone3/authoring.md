# Content admission and selection

Schema 1 and its finite coefficient-domain verifier remain supported unchanged. Schema 2 adds construction/related-idea/structure IDs, primary and alternative techniques, prerequisites, reasoning demand, answer form, explicit difficulty rationale, response format, and per-option misconception explanations. These fields stay private before answering.

`content_pipeline.py` reconstructs each record from a reviewed, versioned mathematical constructor. Constructors can use exact differentiation, an antiderivative plus endpoint certificate, exact limits, recurrences, algebraic identities, or an analytic proof with explicit conditions and separately recorded executable checks. An analytic certificate is an inspectable mathematical argument, not a claim that a CAS or proof assistant proved all its premises. Numerical spot checks are supplementary. Automated/editorial review is not human review.

`content/standalone.py` also admits explicit standalone rational-polynomial tasks with an operation, domain, supplied distractors and metadata. It derives the answer by coefficient calculus and independently checks it symbolically. It does not require registration in the old three-kernel recipe catalogue. Unsupported operations, expressions, proof routes, domains and versions fail closed; adding a new route requires implementing and reviewing its verifier. Artifact hashes alone never authorize new mathematics.

Publication validates canonical hashes and stable IDs, exact choice uniqueness, domains, worked explanations, metadata and all KaTeX strings. Generated artifacts and answer keys remain in ignored `.bank-data`, outside client assets and deployment archives. Authoring source is developer source in the existing repository, never sent to the player as an answer bank.

The selection policy samples a bounded number of indexed slots, weights families rather than instance counts, and penalizes recent family, idea, structure and strategy combinations. It keeps the requested topic, difficulty and tag as hard filters. A constrained random ordering avoids same-family adjacency whenever feasible; it does not impose a rotation. Legacy fluency families retain weight 0.15; authored families use weight 1. Option order remains independently shuffled and saved.

Recent history distinguishes issued (10 minutes), client-reported displayed (one day), and server-accepted attempted (14 days), with decaying weights. A display is a preference signal, never proof of mastery or a graded attempt. Reports map only to the member's immutable server snapshot. Replayed chunks and duplicate answers cannot renew a penalty; lower stages cannot replace attempts. At most 512 entries survive, preserving attempted content before abandoned issued sets. A shared competitive round retains exactly one saved question order for all participants.

Diagnostics distinguish a mathematically impossible family cap, true recent-item exhaustion, bounded sampling limits, and unavoidable adjacency. An unavailable exact filter produces an explicit unavailable response; no model is called, no difficulty is lowered, and no filter is silently widened.

Primary strategy counts use a maintained normalization table rather than one descriptive technique name per family. For example, parameter-ODE and parameter-ODE-with-involution both count as `differential-equation-method`; multiple Fourier constructions count as `Fourier-analysis`. The detailed method remains in provenance and technique drill tags. This preserves precise filters without inflating reported strategy diversity.

The integration editorial veto moves inverse moments, the direct binomial/exponential substitution, and the staircase Laplace exercise into hard fluency. Five additional priority constructions remain useful related variants but are excluded from the strict new-independent-family minimum. Reports show this conservative count separately from selectable labels and related-idea groups.

Personal exposure weights are used only for individual Test/Rapid selection. PvP and Multiplayer begin from the common bank policy with no host-personal history input. Their issued/displayed/attempted observations can still inform a participant's later individual practice, and everyone in a shared round receives its saved order.

For an explicitly authored standalone specification, run `python scripts/bank/content/standalone.py --spec PRIVATE_SPEC.json --out .bank-data/standalone --release UNIQUE_RELEASE --parent VERIFIED_PARENT`. It produces a verified one-item JSONL and a schema-2 manifest usable by the same delta preparation path. The supported operation is `definite-integral` or `derivative-at-point`; coefficients, endpoints and three authored distractor values are bounded exact numerator/denominator pairs. The verifier test fixture documents the complete specification. Do not count this route's test fixtures toward shipped coverage. A future release based on a composed parent must first extend the delta planner's explicit flattened-parent check; it currently stops rather than losing inherited membership.
