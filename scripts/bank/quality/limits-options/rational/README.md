# Ten finite sequence-limit option repairs

This separate immutable candidate layer replaces only the ten unpublished
`q2-repair-m3-limits-easy-rational-sequence-shift` menus. It preserves their
literal statements, mathematical values, Easy classification, construction,
and exposure lineage. The frozen 1,069-record review inventory, 508 metadata
supplements, and baseline records remain unchanged. Parent independent review,
destination-ID screening, admission, and release tests are still required.

Every choice is a reduced positive rational base raised to the same displayed
power. All four literal expressions have the same length in each item. Wrong
routes use reciprocal leading coefficients, constant terms, a finite first
term, its reciprocal, or incorrectly combining a denominator constant with
its coefficient of n. All values arise from those named mistakes; there are
no arbitrary numeric offsets. Across the ten cases the correct value occupies
all four numeric ranks (counts 1, 1, 3, 5). This is a bounded check, not proof
against every possible option-only classifier.

The final expanded rational in the old solution is replaced by its exactly
equal common-form power. Its two preceding leading-coefficient/continuity
steps remain verbatim. The exact old and new conclusion are bound per record.

`repairs.catalog()`, `repairs.build(family, index)`, and `repairs.verify(record)`
provide the exact finite API. `source-records.jsonl` and `source-manifest.json`
guard all original canonical bytes. Unknown families, noninteger indices, and
changed records are rejected. No runtime API writes source files or uses the
network. `repairs.py` as a standalone script regenerates the same candidate
artifact; preserve the frozen directory and write checks into a copy.

Author checks: ten reconstructions, 60 nonzero literal rational differences,
14 negative guards, no opposite pairs, and 110 strict source/formatter
expressions rendered without errors. In the fixed source-ID option screen,
every length predictor scores chance (0.25) in both halves. The only flag is
one deterministic audit-shuffle position (0.4 development, 0.8 held out);
production uses fresh shared shuffles, and the IDs/split were not changed to
suppress this finite-sample flag.
